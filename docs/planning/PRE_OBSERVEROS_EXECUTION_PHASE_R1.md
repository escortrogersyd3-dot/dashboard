# Pre-ObserverOS Execution Phase R1

**Status: PLANNING / RECONSTRUCTION CONTRACT.** This is a bounded phase for work that is safe without a live, audited ObserverOS browser interface. It does not authorize deployment, database creation, credentials, media access, business computation, independent AI, permission decisions, or claims of live integration.

## Objective and exit result

Produce the complete frozen V7 surface as Mock-only, empty-state contracts and presentation shells, then publish one offline HTML showcase. The phase result is `PASS_PREOS_SURFACE_CONTRACTS` only when every OTP below has a verified receipt and the showcase is generated. Every real data path remains `HOLD_LIVE_INTEGRATION` until ObserverOS supplies approved schemas, field classification, authorization behavior, freshness, audit references, and browser-safe access.

## Entry gates and shared constraints

- Before every OTP: clean Dashboard worktree, `main` equals remote, frozen V7 SHA256 equals `cbafbb0fb3944071e7c8605037f7be2aba9389047cc36e2ad1767b5444ce21ec`, dependency receipt is verified, and a unique backup manifest is hash-verified.
- Every admitted OTP has exact UTF-8 SHA256, a GitHub Issue with OTP markers, isolated branch, pull request, local checks, GitHub control-plane audit, merge, receipt, and closed Issue.
- `REUSE` may not be rewritten. `WRAP` may add only V7 exterior, approved future OS binding, identity display, and frozen interaction. Any `CUSTOM` item needs GitHub reuse research before implementation.
- UI may show `LOADING`, `EMPTY`, `STALE`, `UNKNOWN`, `ERROR`, and `PERMISSION`; it must not infer, zero-fill, rank, calculate, or decide access.
- Failure blocks dependent OTPs. Independent OTPs may continue only if their own preflight and scope gates pass. No test standard is lowered to create a pass.

## Required final delivery

The final showcase must visibly distinguish: completed Mock-only surfaces; completed interface proposals; and blocked live dependencies. It must link only local project artefacts and state that ObserverOS owns the future database, facts, calculations, permissions, audit and authoritative status.

## Live integration gate after this phase

No adapter network call may be enabled until an individual ObserverOS interface family has: approved schema, owner, field classification, identity/permission semantics, freshness semantics, safe errors, pagination/rate rules, provenance/audit reference, Mock and negative fixtures, and Dashboard acceptance evidence. The missing gate is recorded as `HOLD_LIVE_INTEGRATION`, never masked by the Showcase.
